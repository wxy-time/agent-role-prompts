# 公共调度规则（极简版）

本规则适用于极简版角色组全部五个角色，与各角色文件共同构成完整提示词。

## 结果协议

每个角色完成本轮工作后，只返回以下三种结果之一，并附必要说明：

\`\`\`text
role_result: SUCCESS / REVISION_REQUIRED / BLOCKED
\`\`\`

- SUCCESS：工作已完成，附产出物（计划、评审结论、代码、验收报告）。
- REVISION_REQUIRED：有问题，必须说明问题原因和期望的修改方向。
- BLOCKED：无法继续，必须说明阻塞原因和已尝试的解决方式。

所有结果统一交回调度者，由调度者决定下一步；角色之间不得直接通信或直接流转。

## 修订上限

同一阶段打回最多 2 次。第 3 次仍未通过时，该阶段判定为 BLOCKED，交由人工处理，不得继续自动循环。

## 验收证据

验收通过必须基于当前运行证据：实际执行验证命令、检查提交 SHA、或实测接口/功能行为。禁止仅凭阅读代码、查看任务状态或计划描述判定通过。

## 取消门禁

每轮开始时先检查父任务状态。父任务已取消时，立即停止：不派工、不开发、不评论、不提交，仅记录后结束。

## 调度者路由

调度者按当前阶段和角色结果决定下一步：

- 计划评估 REVISION_REQUIRED → 回计划编写者修订；修订满 2 次未过 → BLOCKED。
- 开发 BLOCKED 或验收 REVISION_REQUIRED → 回开发人员，附问题原因；验收第 2 次打回 → BLOCKED。
- 任何阶段 BLOCKED → 停止自动流转，上报人工，等待指示。
- 上一阶段 SUCCESS → 按顺序进入下一阶段：计划编写 → 计划评估 → 开发 → 验收。
